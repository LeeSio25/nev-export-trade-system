# 中国新能源汽车出口贸易数据管理系统

《数据库原理》三级项目 · 2025级软件工程6班第3小组（黑科技小组）

技术栈：**HTML + CSS + Flask + MySQL**。页面全部由 Jinja2 服务端渲染，图表用纯 CSS / SVG 绘制，不依赖任何前端框架或 CDN。

> 版本变更记录见 [CHANGELOG.md](CHANGELOG.md)，当前版本 **v1.5**。

---

## 一、快速开始

### 1. 准备环境

```bash
pip install -r requirements.txt      # Flask 3.1.3 + PyMySQL 1.2.3
```

需要 **Python 3.9+**（开发环境 3.13.14）与 **MySQL 8.0+**（开发环境 9.4.0）。

### 2. 导入数据库

```bash
mysql -u root -p < sql/cnev_export_trade_db.sql
```

脚本自带 `CREATE DATABASE` 与 `DROP TABLE IF EXISTS`，**可重复导入**，导入后得到 18 张表、436 行示例数据、22 个外键、29 个 CHECK 约束。

### 3. 配置连接（口令不进源码）

**源码里没有任何明文口令。** 数据库口令按下面顺序取：

1. 环境变量 `DB_PASSWORD`（推荐，换机器只改环境变量）
2. 同目录 `secrets_local.py` 里的 `DB_PASSWORD`（本地开发用，已写进 `.gitignore`，不随包分发）

```bash
# 方式一：环境变量
set DB_PASSWORD=你的MySQL口令

# 方式二：本地文件
copy secrets_local.example.py secrets_local.py   # 然后编辑，填上 DB_PASSWORD
```

其余连接参数也可用环境变量覆盖：`DB_HOST / DB_PORT / DB_USER / DB_NAME / PORT / SECRET_KEY`。
会话密钥 `SECRET_KEY` 若未配置，启动时随机生成（只影响重启后未读的提示条，不影响功能）。

若两处都没配，启动会直接提示「没有拿到数据库口令」，不会抛堆栈。

### 4. 启动

双击 **`run.bat`**，或命令行执行 `python app.py`，浏览器打开 <http://127.0.0.1:5000>。

> 启动前脚本会自检数据库连接，连不上会直接给出中文原因（密码错、服务没起、库不存在）。

## 三、核心设计：不写死任何字段

启动后从 `information_schema` 读取真实的表、列、主键、外键，动态生成：

- 左侧菜单（18 张表按 6 大模块分组，带行数角标）
- 表头（列注释的中文名）与单元格（外键自动带出关联表名称）
- 新增/编辑表单控件：
  | 字段特征 | 控件 |
  |---|---|
  | 外键 | 下拉框，选项来自关联表（显示「编号 · 名称」）|
  | 注释含「A/B/C」或「Y/N」 | 下拉框（如 未发货/在途/到港/签收）|
  | date | 日期选择器 |
  | int / decimal | 数字框（整数步长 1，小数步长 0.01）|
  | 长文本 | 多行文本域 |
  | 主键（编辑时） | 只读 |

好处：文档里的表名与数据库真实表名并不一致（文档 `Enterprise`，实际 `autoenterprise`；`Model` → `exportmodel`；`Base` → `productionbase`），程序自动适配，不受影响。

## 五、统计模块清单

| 统计 | 用到的 SQL 能力 |
|---|---|
| 按年份出口趋势 | 按年分组 + LEFT JOIN 汇总 |
| 月度出口节奏 | 日期格式化分组 |
| 按目的国出口排名 | 三表连接 + 分组 |
| “一带一路”出口占比 | CASE 表达式分组 |
| 企业出口排名 | 四表连接 + COUNT(DISTINCT) |
| 车型出口排名 | 明细 ⋈ 车型 ⋈ 订单 + 汇率子查询折算 |
| 政策生效后出口情况 | 相关子查询（多处标量子查询）+ EXISTS 过滤无订单政策 |
| 认证到期预警 | 三表连接 + DATEDIFF + CASE 分级 |
| 承运商运输时效 | LEFT JOIN + 条件 + AVG |
| 报关与退税汇总 | 三表连接 + SUM 汇总（金额折人民币）|
| 币种结构与人民币折算 | 订单 ⋈ 币种表 + 标量子查询取最新中间价 |

> 库中目前只有 2026 一个年度的订单，因此「按年份出口趋势」的折线会自动按月展开，页面上有黄色小标签说明，表格仍按年展示。

> 「政策生效后出口情况」原口径为「政策生效前后各 180 天对比」，但库中 12 条政策生效于 2020-01 ~ 2026-01，
> 而 10 笔订单全部落在 2026-06 ~ 2026-10，两个时间窗完全不相交，统计必然全 0。
> 现改为「政策生效至今累计」，既能算出真实订单（欧盟反补贴税 3 单 20 台、泰国 EV3.5 2 单 13 台），也保留了相关子查询这一演示点。

## 六、使用注意

1. **主键在编辑时不可改**（数据库层面改主键会破坏外键引用），需更换请删除后重建。
2. 表单里留空的非必填字段写入 `NULL`，不是空字符串。
3. 删除被引用的记录会被外键约束拦下，页面会提示「存在引用该记录的子表数据，不能删除」。
4. SQL 演示台只允许 `SELECT / WITH / SHOW / DESC / EXPLAIN`，且一次一条。
5. 演示前建议先开着 MySQL 服务，`config.py` 里的密码与本机一致。
6. **金额口径**：订单合同额有 USD / EUR / THB / AUD / MYR / DKK 等多种币种，页面所有汇总金额一律按「该币种最新中间价」折算成人民币后再相加，卡片与统计表头都标注了「折￥ / 折人民币」，不做跨币种直接相加。
   汇率表目前只有 202609、202610 两个月，若答辩时被问到「为什么不用当月汇率」，可回答：当月汇率缺失时回退到该币种最新中间价，SQL 演示台的「汇率换算」正好演示了 `COALESCE(当月, 最新)` 的写法。
7. 页面支持浏览器打印（Ctrl+P）导出 PDF，会自动隐去侧边栏、工具栏与操作按钮，适合交报告截图。
